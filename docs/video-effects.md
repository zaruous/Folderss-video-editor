# 동영상 효과 — 클립 위에 그리는 효과

전환 효과가 두 클립 사이에서 바뀌는 것이라면, 동영상 효과는 클립 하나의 그림 위에 그리는 것이다(첫 효과: **스캔 라인**, 그다음 **흔들림·줌** 다섯).
효과는 코드에 든 목록에서 고르고, 프로젝트 파일에는 값만 저장한다.

## 1. 구조

| 곳 | 내용 |
|---|---|
| `Core/VideoEffects.cs` | 클립의 효과 값(`ClipEffect`), 효과 정의(`VideoEffectDef` — 이름·묶음·설명·매개변수·그리는 함수), 목록(`VideoEffects.All`), 값 검사·고치기, 효과 탭 썸네일 인수 |
| `Core/ScanLine.cs` | 스캔 라인 정의·모양 계산·그리는 함수 |
| `Core/ShakeZoom.cs` | 흔들림·줌 다섯(카메라 흔들림·지진·하트비트·빠른 줌·줌 바운스) 정의·움직임 계산·그리는 함수(perspective 하나) |
| `Core/RenderGraph.cs` | 클립 체인에 효과를 잇는 곳(`EffectChain`), 인물 마스크 입력, 맞춤의 그림 크기 |
| `Ui/MediaPanel.cs` | [효과] 탭 맨 위 "동영상 효과" 썸네일·[고른 클립에 넣기]·끌어 놓기 |
| `Ui/PropertyPanel.cs` | 속성 패널 [효과] 탭(동영상·사진 클립): 매개변수·색·[사람에게만]·빼기·인물 마스크 상태 |

- 클립의 `Effects`는 `ClipEffect` 목록이다: `Id`(효과 id), `Values`(매개변수 키 → 숫자), `Color`(#RRGGBB), `PersonOnly`.
  - 효과를 넣을 때 기본값을 모두 적어 둔다(나중에 기본값이 바뀌어도 넣은 효과는 그대로 보이게).
  - 목록 순서대로 그린다(뒤 효과가 위). 클립 하나에 8개까지.
  - 동영상·사진 클립에만 들어간다. 글자 클립·소리 클립은 효과가 없다(사운드 분리로 만든 소리 클립에도 따라가지 않는다).
- 사용자 효과(효과 폴더)는 없다. 효과 파일·프로젝트 파일에서 필터 글을 받으면 남이 만든 파일이 필터 그래프를 바꿀 수 있어서다 —
  그리는 방법은 플러그인 코드에만 있고, 파일에서 오는 것은 숫자와 #RRGGBB뿐이다.

| 묶음 | 효과 | id | 파일 | 사람에게만 |

| 빛 | 스캔 라인 | `scan-line` | `ScanLine.cs` | 있음 |
| 흔들림·줌 | 카메라 흔들림 | `camera-shake` | `ShakeZoom.cs` | 없음(그림 전체를 움직임) |
| 흔들림·줌 | 지진 | `earthquake` | `ShakeZoom.cs` | 없음 |
| 흔들림·줌 | 하트비트 | `heartbeat` | `ShakeZoom.cs` | 없음 |
| 흔들림·줌 | 빠른 줌 | `punch-zoom` | `ShakeZoom.cs` | 없음 |
| 흔들림·줌 | 줌 바운스 | `zoom-bounce` | `ShakeZoom.cs` | 없음 |

### 효과 더하기

1. `Core/` 아래에 정의(`VideoEffectDef`)와 그리는 함수를 만든다(`ScanLine.cs`가 본보기).
2. `VideoEffects.All`에 한 줄 더한다.

효과 탭 썸네일, 속성 패널의 매개변수 줄(숫자 슬라이더·색), 저장·검사·복사, 렌더 그래프 자리는 정의에서 저절로 나온다.

그리는 함수의 규칙(`VideoEffects` 설명에도 있음):

- 받는 흐름은 **틀 크기**(`EffectRender.Width`×`Height`)의 gbrap이다. 돌려주는 글을 지금 체인 뒤에 그대로 붙이고, 글이 끝난 곳의 흐름이 효과를 입힌 클립이다(같은 크기, 알파 그대로).
- 라벨은 `EffectRender.Label`로 시작한다. 수식에 `st()`·`ld()`·`random`·`time`을 쓰지 않는다(조각마다 값이 섞이거나 그릴 때마다 달라진다).
- 한 체인에 크기 바꾸기(`scale`)를 둘 잇지 않는다(전환 끝에서 FFmpeg가 멈춘 적이 있다 — [전환 효과](transitions.md)).
- 숫자는 `RenderGraph.N`으로만 쓴다. 길이 값(px 매개변수)은 `EffectRender.PixelScale`을 곱한다.
- 시각은 `t + EffectRender.TimeOffset`(클립 안 시각)으로 쓴다. `t`가 없는 필터(perspective)는 프레임 번호로: `(in − 1) ÷ fps + TimeOffset`(흐름은 fps로 고르게 맞춘 뒤다).
- 그림 전체를 움직이는 효과처럼 사람 자리에만 칠할 수 없는 효과는 정의에 `AllowsPersonOnly = false`를 준다(속성 패널에 [사람에게만]이 없고, 켜진 값은 열 때 끄고 그릴 때도 무시).
- [화면에 맞춤]의 그림 크기는 `EffectRender.PictureWidth`×`PictureHeight`(틀 가운데, 0이면 틀 전체) — 그림을 움직이는 효과가 빈 곳은 두고 그림 안에서만 움직이는 데 쓴다.

## 2. 렌더 그래프에서의 자리

```
원본(-ss·-t·속도·fps) → 틀 맞춤(scale 하나 — 효과가 있으면 바로 gbrap으로) → [맞춤이면 틀 크기로 투명하게 채움]
  → 효과 1 → 효과 2 … → 회전 → 불투명도 → 디졸브 페이드 → 시각 맞춤 → 얹기 / 전환 조각
```

- 효과는 틀 계산(맞춤·채우기·늘이기·흐린 배경, 크기 배율) 뒤, 회전 앞에서 돈다. 그래서 클립과 함께 옮기고 돌고 흐려지고 전환된다(xfade 묶음 안에서도 같다).
- [화면에 맞춤]은 남는 곳이 비어 그림이 틀보다 작다. 효과 앞에서 틀 크기로 투명하게 채운다(`pad … color=black@0`, 그림 자리는 그대로) — 그래서 효과는 늘 틀 크기 그림을 받고, 빈 곳은 계속 투명하다.
  그림 크기는 원본 크기로 틀 맞춤의 scale과 같은 계산을 해(`RenderGraph.FitSize`) `EffectRender.PictureWidth`·`PictureHeight`로 넘긴다(원본 크기를 모르면 0 = 틀 전체).
- 크기: 효과의 px 값은 프로젝트 픽셀이다. `PixelScale` = 출력 너비 ÷ 프로젝트 너비 × 클립 크기 배율 ÷ 재생 축소(수식 전환 묶음의 재생). 크기 50% 클립은 선도 절반이다.
- 시각: 흐름의 0초는 그리기 시작(`segStart`)이다. 효과 시각 = `t + (segStart − 클립 시작)`초라서, 멈춘 화면(그 프레임부터 그림)·재생(앞에서부터 이어 그림)·내보내기가 같은 프레임을 같게 그린다(시험: 한 장 그리기와 이어 그리기의 픽셀 차 0).
- 효과가 없는 클립의 그래프는 예전과 같다(`format=rgba`).

## 3. 스캔 라인

가는 흰 선(속)을 넓은 색 빛(번짐, 기본 파랑 `#2F7BFF`)이 감싼 띠가 클립 위에서 아래로 훑고 지나간다.

- 선은 **아래로 휜다** — 양끝이 높고 가운데가 처진 얕은 U(휘어짐 0이면 곧은 선).
- 움직임: 주기의 앞 80% 동안 훑고(빨리 들어와 가운데서 머물다 빨리 나감) 나머지 20%는 선이 보이지 않다가 다시 처음부터.
- 어두운 곳을 지날 때는 그 어둠만큼 위아래로 지그재그로 떨린다(일그러짐).
- 스크린으로 섞어 화면을 밝게만 한다. 클립의 알파는 그대로다(투명한 곳은 투명하게).

| 매개변수 | 키 | 범위(기본) | 뜻 |
|---|---|---|---|
| 빛 번짐 | `glow` | 0~150px (40) | 흰 선 둘레 색 빛의 폭. 빛은 이 거리에서 0이 된다 |
| 굵기 | `core` | 1~20px (3) | 가운데 흰 선의 굵기 |
| 휘어짐 | `bend` | 0~100% (35) | 가운데가 처지는 깊이 — 100%면 틀 높이의 20% |
| 일그러짐 | `jitter` | 0~100% (40) | 어두운 곳의 떨림 — 100%면 80px(틀 크기 배율만큼, FFmpeg displace 한도 127px까지) |
| 속도 | `period` | 0.8~6초 (2.4) | 한 번 훑고 다시 시작할 때까지 걸리는 시간(작을수록 빠름) |
| 불투명도 | `opacity` | 0~100% (100) | 선과 빛의 세기 |
| 색 | `color` | #RRGGBB (#2F7BFF) | 빛 번짐의 색(가운데 선은 흰색) |

### 그리기

```
띠 한 장: color(1프레임) → geq(R = 속, G = 번짐) → colorchannelmixer(속 = 흰색, 번짐 = 색, × 불투명도) → tpad(구간 끝까지 그대로)
[일그러짐] 무늬: 두 배 너비 한 줄 geq(꺾은선, 가운데 128) → scale(띠 높이, neighbor) → tpad → crop(1초에 12번 다른 자리)
          어둠: 클립 → crop(띠 자리, 시각 수식) → gray → lut(밝기 140 위 0 ~ 40 아래 다)
          무늬 × 어둠(blend multiply128) = 세로 지도, 가로 지도 = 128 → displace(띠)
검은 틀(color, 틀 크기) + 띠 → overlay(y = 시각 수식) [→ × 인물 마스크(blend multiply)]
→ 클립과 blend: R·G·B는 screen, 알파는 multiply(선 쪽 알파 255 → 클립 알파 그대로)
```

- 띠는 한 번만 그린다(수식 `geq`는 한 장, 나머지는 `tpad`로 같은 그림을 늘인다). 매 장 드는 것은 검은 틀·얹기·섞기와 일그러짐 쪽의 띠 크기 처리뿐이다.
- 휜 선: 띠 안 가로 위치 −1~1에서 선 높이 = 여백 + 처짐 × (1 − x²). 선까지의 거리는 기울기만큼 줄여 굵기가 고르다(`hypot`).
  여백은 번짐 폭 + 떨림 폭 + 1px라 번짐이 띠 가장자리에 닿기 전에 0이 된다(띠 위아래에 딱딱한 줄이 없다).
- 시각 수식(`ScanLine.Progress`와 같은 식): `u = min(1, mod(t + 앞선 초, 주기) / (주기 × 0.8))`, 자리 = `0.25u + 0.75(0.5 + 4(u − 0.5)³)`,
  띠 윗변 = `−띠 높이 + (틀 높이 + 띠 높이) × 자리`. 쉬는 동안은 자리 1(틀 아래로 다 지나감)이다.
- 떨림 무늬는 같은 클립 시각이면 같은 자리를 잘라 쓴다(`floor((t + 앞선 초) × 12)`) — 이어 그려도 한 장 그려도 같다.
- 떨림은 띠 크기에서만 민다. 띠가 틀보다 높아지면(아주 작은 틀) 떨림 폭을 줄이고, 1px 아래면 떨리지 않는다.

### 걸리는 시간 (12스레드 PC, FFmpeg 개발판 N-115012)

| 1080p, 2초(60장) `-f null` | 장당 |
|---|---|
| 효과 없음(320×240 동영상을 채우기로) | 6.2ms |
| 스캔 라인(기본값, 떨림 포함) | 15.0ms (+8.8ms) |
| 스캔 라인(떨림 없이) | 12.2ms (+6.0ms) |

- 목표(장당 +25ms 안팎) 안이다. 시험 `Cost_At1080p_StaysWithinBudget`이 이 셋을 재서 출력한다.
- 띠를 그리는 수식(`geq`)은 그래프마다 한 번이다. 1080p 틀에서 약 0.1~0.2초라, 멈춘 화면을 전체 화질로 그릴 때 그만큼 늦다(1/2 화질이면 약 1/4).

## 4. 흔들림·줌 (카메라 흔들림·지진·하트비트·빠른 줌·줌 바운스)

클립 그림을 틀 안에서 옮기고 돌리고 키우는 효과 다섯이다(효과 탭 묶음 "흔들림·줌", `Core/ShakeZoom.cs`).

- **카메라 흔들림**: 손에 든 카메라처럼 부드럽게 출렁인다. 가로·세로·돌림이 각각 서로 맞지 않는 빠르기의 사인 합이다
  (가로 0.67·1.61·3.37Hz, 세로 0.83·1.97·3.71Hz, 돌림 0.47·1.29Hz — 낮은 것이 크고 높은 것은 작게, × 빠르기). 같은 시각이면 늘 같은 자리다.
- **지진**: 1초에 9번(× 빠르기) 새 자리로 홱 옮긴다 — 마디마다 정해진 값(`fract(sin(마디 × 12.9898 + 씨앗) × 43758.5453)`, random 대신)으로
  마디의 앞 45% 동안 (1 − cos)/2로 옮기고 나머지는 머문다. 여기에 빠른 출렁임(2.3·2.9Hz)을 25% 섞는다. 세로는 가로의 80%, 세기 1px마다 0.025도(2.5도까지) 돈다.
  [흐림]은 움직임이 번진 듯 살짝 흐리게 한다.
- **하트비트**: 박자마다 0.07초 동안 (1 − cos)/2로 쿵 커지고 0.12초를 시간 상수로 가라앉는다. 0.22초 뒤 두 번째 작은 박동(세기는 [두 번째 박동]).
  빠른 박자에서는 커지는·가라앉는 시간을 한 박의 1/8, 두 번째 박동을 1/3까지 줄여 다음 박 전에 가라앉는다.
- **빠른 줌**: [시작]부터 [길이] 동안 4차 곡선(빨리 시작해 천천히 멈춤)으로 1 → 1 + 배율, 그 뒤 머문다. 배율이 −면 1 + |배율|에서 1로 빠져나온다. 중심은 그림 안 어디든.
- **줌 바운스**: 주기의 앞 절반은 탄성 곡선으로 1 → 1 + 배율(넘쳐 더 커졌다 돌아옴), 뒤 절반은 돌아오며 1배 바닥에서 튄다(|1 − 곡선| — 1배 아래로 가지 않음).
  탄성 곡선 = 1 − e^(−감쇠·u)·cos(출렁임·u)·(1 − u), 감쇠 = 3 + 3(1 − 탄성), 출렁임 = π(1 + 3·탄성) — u = 1에서 꼭 1이고 0 아래로 가지 않는다.
  [반복] N(1 이상)이면 N번째 주기의 앞 절반에서 커진 뒤 머문다(1 = 한 번 튀어 커진 채 머묾, 0 = 끝없이).

| 효과 | 매개변수(키) | 범위(기본) | 썸네일 값 |
|---|---|---|---|
| 카메라 흔들림 | 가로 세기(`horizontal`) · 세로 세기(`vertical`) · 회전(`rotate`) · 빠르기(`speed`) | 0~150px(18) · 0~150px(12) · 0~8°(0.8) · 0.2~4배(1) | 60·45·3°·2배 |
| 지진 | 세기(`amount`) · 빠르기(`speed`) · 흐림(`blur`) | 0~200px(30) · 0.3~3배(1) · 0~100%(40) | 70px·흐림 30 |
| 하트비트 | 세기(`amount`) · 박자(`bpm`) · 두 번째 박동(`second`) | 1~50%(12) · 30~200bpm(80) · 0~100%(60) | 40%·120bpm |
| 빠른 줌 | 배율(`zoom`) · 길이(`duration`) · 시작(`start`) · 중심 가로(`centerx`) · 중심 세로(`centery`) | −200~200%(40) · 0.05~2초(0.3) · 0~60초(0) · 0~100%(50) · 0~100%(50) | 80%·0.25초·0.3초 |
| 줌 바운스 | 배율(`zoom`) · 주기(`period`) · 탄성(`elastic`) · 반복(`repeat`) | 5~100%(25) · 0.4~4초(1.6) · 0~100%(60) · 0~10회(0) | 40%·1.5초 |

- 흔드는 거리(px)는 프로젝트 픽셀이라 `PixelScale`을 곱한다(크기 50% 클립·줄인 재생에서는 그만큼 작게). 그림 크기의 20%까지만 흔든다.
- [반복]은 소수점 아래를 버린다(슬라이더 값 2.7 = 2회).

### 그리기

```
[맞춤이면 crop(그림 자리)] → perspective(x0~y3 = 프레임마다 푸는 수식, eval=frame) [→ 지진 흐림: convolution 3×3(R·G·B)] [→ 맞춤이면 pad(틀 크기, 투명)]
```

- 효과 하나가 perspective 하나다(라벨로 끊지 않고 지금 흐름에 그대로 잇는다). 출력의 점 q(픽셀 가운데)는 원본의 `c + R(돌림)·(q − c) ÷ 배율 + 옮김`을 읽는다(c = 중심) —
  이 식으로 출력 모서리 (0,0)·(W,0)·(0,H)·(W,H)가 읽을 원본 자리를 수식으로 주면(`sense=source`) 평행사변형이라 perspective가 확대·돌림·옮김을 한 번에 그린다.
  1/256픽셀 단위 선형 보간이라 느린 줌·작은 흔들림도 정수 계단 없이 매끄럽다(배율 1·돌림 0·옮김 0이면 원래 그림과 픽셀 차 0).
- 크기 바꾸기를 잇지 않는다: 체인의 scale은 틀 맞춤 하나뿐이고 출력은 늘 받은 크기다. zoompan은 읽는 자리를 정수 픽셀로 잘라 느린 줌이 떨리고 프레임을 따로 다뤄 쓰지 않았고,
  rotate + overlay/crop은 옮김이 정수 픽셀이라 흔들림이 계단지고 줌을 못 한다.
- perspective 수식에는 시각(`t`)이 없어 프레임 번호(`in`, 1부터)로 잰다: 시각 = `(in − 1) ÷ fps + 앞선 초`. 효과가 받는 흐름은 fps로 고르게 맞춘 뒤라 n번째 프레임이 n ÷ fps초다
  (시험: 한 장 그리기와 이어 그리기의 평균 픽셀 차 0.001 이하).
- **빈 가장자리가 없다**: perspective는 그림 밖을 읽으면 가장자리 픽셀을 늘인다(투명해지지는 않음). 흔들림은 흔드는 거리만큼 미리 고정 배율로 키워 그림 밖을 읽지 않는다 —
  배율 = max(1, (W + H·sin 돌림) ÷ (W − 2·가로 거리), (H + W·sin 돌림) ÷ (H − 2·세로 거리))(`ShakeZoom.CoverZoom` — 돌리고 옮긴 읽는 자리의 바깥 상자가 그림 안).
  기본값의 1080p는 약 1.05배, 320×240 시험 화면은 1.14배. 줌은 늘 1배 이상이고 중심을 두고 키우므로 읽는 자리가 그림 안이다.
- **화면에 맞춤**: 틀 가운데의 그림 자리(`PictureWidth`×`PictureHeight`)만 잘라 움직이고 다시 투명하게 채운다 — 빈 곳(아래 트랙이 보이는 곳)은 그대로 투명하고,
  그림은 제자리(자기 사각 안)에서 흔들리고 커진다. 원본 크기를 모르면(프로젝트 미디어 목록에 없음) 틀 전체를 움직인다 — 빈 곳의 투명한 가장자리가 늘어나 투명하게 남지만 그림이 빈 곳 쪽으로 움직인다.
  채우기·늘이기는 틀이 곧 그림이고, 흐린 배경은 틀 전체(흐린 배경 + 그림)가 함께 움직인다.
- 지진 흐림: 가로 [a 8 a] × 세로 [b 8 b]를 곱한 3×3 행렬(FFmpeg convolution, R·G·B만 — 알파 면은 행렬을 주지 않아 그대로). a·b = round(8 × 흐림 × min(1, 흔드는 거리 ÷ 20px)) —
  줄인 재생 크기·작은 흔들림에서는 그만큼 약하다. 3×3이라 흐림 반지름은 1px까지다(avgblur는 +8ms 남짓이라 쓰지 않음, 3×3은 +2~3ms).
- 사람에게만은 없다(`AllowsPersonOnly = false`): 그림 전체를 움직이는 효과라 사람 자리만 따로 움직일 수 없다. 속성 패널에 [사람에게만]이 없고, 켜진 채 저장된 값은 열 때 끄며 그릴 때도 마스크를 읽지 않는다.

### 걸리는 시간 (12스레드 PC, FFmpeg 개발판 N-115012)

| 1080p, 2초(60장) `-f null`, 장당 늘어난 시간 | 부하가 적을 때(효과 없음 5.5~6ms) | 다른 작업이 CPU를 함께 쓸 때(효과 없음 7~11ms) |
|---|---|---|
| 카메라 흔들림(기본값) | +13~16ms | +19~25ms |
| 지진(기본값, 흐림 포함) | +15~16ms | +15~19ms |
| 하트비트 | +12~15ms | +10~13ms |
| 빠른 줌 | +13~14ms | +8~12ms |
| 줌 바운스 | +13~15ms | +8~22ms |

- 거의 perspective 하나의 몫이다: 프레임마다 픽셀마다 읽을 자리를 새로 계산하고(약 5ms, `eval=frame`) 네 면을 선형 보간한다(약 9ms). 돌림이 있어도 같다.
- 맞춤은 crop(복사 없음)·pad(한 장 복사, 약 1ms)가 더해진다. 시험 `ShakeZoomRenderTests.Cost_At1080p_StaysWithinBudget`이 다섯을 재서 출력한다.

## 5. 사람에게만 (인물 마스크)

- 효과의 [사람에게만]을 켜고 원본의 인물 마스크가 있으면(`RenderOptions.PersonMasks.Find(원본)` — 미리 보기·재생·내보내기는 `RenderEnvironment.PersonMasks`) 사람 자리에만 칠한다.
- 마스크는 원본과 같은 시간축의 흑백 동영상(사진 원본이면 흑백 PNG, 흰색 = 사람)이고 원본보다 작아도 된다.
  - 렌더 그래프는 마스크를 원본과 **똑같이** 읽는다: 같은 `-ss`·`-t`, 같은 속도·`fps`·끝 멈춤, 사진이면 같은 `-loop 1`(`RenderGraph.MediaSource`).
  - 클립과 같은 맞춤으로 틀 크기에 맞춘다 — 크기 바꾸기 한 번(채우기: 키워 가운데 자르기, 늘이기: 틀 크기로, 맞춤·흐린 배경: 줄여 가운데에 두고 남는 곳은 검정).
    마스크는 모델 크기(32의 배수)라 원본과 비율이 조금 달라, 마스크 자신의 비율이 아니라 원본 크기로 FFmpeg의 비율 맞춤과 같은 계산을 해 구한 클립 그림 크기로 늘인다(`RenderGraph.FitSize`) — 가장자리까지 겹친다.
  - 마스크는 원본 화면 시작부터 만든 것이라, 화면이 파일보다 늦게 시작하는 원본은 그만큼(`MediaInfo.VideoStart`) 당겨 읽는다.
  - 효과의 선(검은 틀에 얹은 띠)에 마스크를 곱한 뒤 섞는다(`blend=all_mode=multiply`). 마스크가 검은 곳은 선이 0이라 스크린으로 섞어도 클립 그대로다.
  - 사람에게만 효과가 여럿이면 마스크 흐름을 `split`으로 나눠 쓴다.
- 마스크가 아직 없으면 클립 전체에 칠한다(알파는 그대로). 속성 패널에 "인물 마스크가 없습니다"와 [인물 마스크 만들기]가 보인다
  (`EditorCommands.BuildPersonMask` — 마스크 만들기는 인물 분리 작업). 만든 뒤에는 "인물 마스크 준비됨"(패널을 갱신할 때마다 디스크에서 확인한다).
- 제공자가 없거나 실패하면(예외) 마스크 없이 그린다 — 미리 보기·내보내기가 멈추지 않는다.
- 사람에게만이 없는 효과(`VideoEffectDef.AllowsPersonOnly = false` — 흔들림·줌처럼 그림 전체를 움직이는 효과): 속성 패널에 [사람에게만]이 없고,
  켜진 채 저장된 값은 열 때 끄며(`VideoEffects.Clean`), 메모리에서 켜져 있어도 렌더 그래프가 마스크를 찾지도 읽지도 않는다.

## 6. 프로젝트 파일

- `Effects`는 효과가 없으면 쓰지 않는다 — 예전 파일과 형식 번호(2)가 그대로다.
- 너그럽게 읽는다: `Effects`가 목록이 아니면 효과 없음, 형식이 틀린 항목(숫자 자리에 글 등)은 그 항목만 버린다(`LenientListConverter`).
- 열 때 고치기(`VideoEffects.Clean`, 프로젝트 파일은 남이 만든 것일 수 있다):
  - 동영상·사진 클립에만, 8개까지. 빈 항목과 id 형식(영문 소문자로 시작하는 소문자·숫자·`-` 48자)이 아닌 항목은 버린다.
  - 아는 효과: 숫자는 매개변수 범위 안으로(NaN·무한대는 기본값), 모르는 키는 버리고, 색은 대문자 #RRGGBB로(알파는 빼고, 잘못된 색은 기본 색). 빠진 값은 기본값으로 채운다.
  - **모르는 효과는 남겨 두고 그리지 않는다** — 새 판에서 만든 효과가 든 프로젝트를 이 판에서 열어 저장해도 사라지지 않게(전환 효과의 모르는 id와 같은 방식).
    값은 형식이 맞는 키의 유한한 숫자 32개까지, 색은 #RRGGBB이거나 없음. 속성 패널에는 "알 수 없는 효과"와 [빼기]만 보인다.
- 나누기(분할)·복사·붙여넣기는 효과 목록을 깊게 복사한다(`Clip.CloneWithNewId`) — 한쪽 값을 바꿔도 다른 쪽은 그대로.
- 모든 고치기는 실행 취소에 남는다(`EditorCommands.EditClip`). 슬라이더를 끄는 동안은 한 단계로 합치고(매개변수마다 다른 합치기 키), 값을 보이기만 해서는 편집이 생기지 않는다.

## 7. 화면

- 미디어 패널 [효과] 탭 맨 위 **동영상 효과**: 썸네일(합성 그림에 실제로 그린 1.5초 띠 15칸, 마우스를 올리면 움직임 — 데이터 폴더`\cache\video-effects\<해시>.png`).
  - [고른 클립에 넣기]·두 번 누르기: 고른 동영상·사진 클립마다 효과를 더한다. 타임라인의 클립으로 끌어 놓아도 된다(동영상·사진 클립 위에서만 놓인다).
  - 넣으면 그 클립을 고르고 속성 패널 [효과] 탭을 연다.
- 속성 패널 **[효과]** 탭(동영상·사진 클립만): 효과마다 이름·[빼기], 매개변수 줄, [사람에게만](사람에게만이 있는 효과만). 사람에게만을 켠 효과가 있으면 인물 마스크 상태와 [인물 마스크 만들기].

## 8. 시험

- `VideoEffectsTests`(Core): 저장·빠짐·너그러운 읽기, 범위·색·모르는 효과 고치기, 동영상·사진에만, 나누기·복사의 깊은 복사,
  그래프 자리(틀 맞춤 뒤·회전 앞, 체인의 scale 하나), 맞춤 채우기, 클립 안 시각(가운데부터 그리기), 인물 마스크 입력(원본과 같은 `-ss`·`-t`·속도, 사진 반복, 찾았을 때만), xfade 조각, 재생 축소·크기 배율, 색 넣기 막기.
- `VideoEffectsRenderTests`(FFmpeg): 띠의 높이가 시각 식과 맞고 뒤 시각에 더 아래·가운데가 처짐·쉬는 동안 없음, 마스크(사진·동영상)의 흰 쪽에만,
  알파(투명한 곳·맞춤의 빈 곳은 아래 트랙 그대로), 어두운 곳의 떨림, 한 장 그리기 = 이어 그리기, 전환·재생(수식 전환 묶음)에서 멈추지 않음, 썸네일 띠, 1080p 걸리는 시간.
- `VideoEffectsTests`(화면): 효과 탭에서 넣기 → 미리 보기가 바뀜, 슬라이더 끄기 = 실행 취소 한 단계, 색, 빼기·되돌리기, 끌어 놓기, 사람에게만·마스크 상태·[인물 마스크 만들기], 글자 클립에는 없음,
  카메라 흔들림에는 매개변수 줄만 있고 [사람에게만]은 없음.
- `ShakeZoomTests`(Core): 목록 순서·묶음·매개변수·썸네일 값, 사람에게만 끄기·마스크 안 읽음, 효과마다 perspective 하나·체인의 scale 하나·금지 함수 없음, 프레임 번호 시각(가운데부터·23.976fps),
  맞춤의 그림 자리(crop·pad, 홀수 차이 버림, 원본 크기를 모를 때), 지진 흐림 행렬, 크기 배율, 흔들어도 그림 밖을 읽지 않음(여러 화면 크기·최대값), 하트비트·빠른 줌·줌 바운스 곡선.
- `ShakeZoomRenderTests`(FFmpeg): 표지(흰 네모)의 자리·크기가 움직임 계산과 맞음(흔들림 ±0.6~0.8px, 줌 배율 ±0.025), 지진이 홱홱 뛰고 흐림이 가장자리를 번지게 함,
  테두리 사진으로 빈·늘인 가장자리 없음, 맞춤의 빈 곳은 아래 트랙 그대로·그림 자리는 꽉 참, 한 장 그리기 = 이어 그리기, xfade·재생(수식 전환 묶음)에서 멈추지 않음, 썸네일 띠, 1080p 걸리는 시간.
