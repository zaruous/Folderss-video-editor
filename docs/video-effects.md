# 동영상 효과 — 클립 위에 그리는 효과

전환 효과가 두 클립 사이에서 바뀌는 것이라면, 동영상 효과는 클립 하나의 그림 위에 그리는 것이다(첫 효과: **스캔 라인**).
효과는 코드에 든 목록에서 고르고, 프로젝트 파일에는 값만 저장한다.

## 1. 구조

| 곳 | 내용 |
|---|---|
| `Core/VideoEffects.cs` | 클립의 효과 값(`ClipEffect`), 효과 정의(`VideoEffectDef` — 이름·묶음·설명·매개변수·그리는 함수), 목록(`VideoEffects.All`)과 묶음 차례(`Groups()`), 값 검사·고치기, 효과 탭 썸네일 인수·바탕 그림(`PreviewSource`) |
| `Core/ScanLine.cs` | 스캔 라인 정의·모양 계산·그리는 함수 |
| `Core/RenderGraph.cs` | 클립 체인에 효과를 잇는 곳(`EffectChain`), 인물 마스크 입력 |
| `Ui/MediaPanel.cs` | [효과] 탭: 맨 위 동영상 효과(묶음 제목·[묶음] 고르기·썸네일 칸·[고른 클립에 넣기]·끌어 놓기), 그 아래 전환 효과 — 탭 전체가 스크롤 |
| `Ui/TileGrid.cs` | 효과 탭 썸네일 칸 놓기(폭에 맞춰 칸 수를 정한 같은 크기 칸)와 16:9 썸네일 틀 |
| `Ui/PropertyPanel.cs` | 속성 패널 [효과] 탭(동영상·사진 클립): 이름 옆 묶음·매개변수·색·[사람에게만]·빼기·인물 마스크 상태 |

- 클립의 `Effects`는 `ClipEffect` 목록이다: `Id`(효과 id), `Values`(매개변수 키 → 숫자), `Color`(#RRGGBB), `PersonOnly`.
  - 효과를 넣을 때 기본값을 모두 적어 둔다(나중에 기본값이 바뀌어도 넣은 효과는 그대로 보이게).
  - 목록 순서대로 그린다(뒤 효과가 위). 클립 하나에 8개까지.
  - 동영상·사진 클립에만 들어간다. 글자 클립·소리 클립은 효과가 없다(사운드 분리로 만든 소리 클립에도 따라가지 않는다).
- 사용자 효과(효과 폴더)는 없다. 효과 파일·프로젝트 파일에서 필터 글을 받으면 남이 만든 파일이 필터 그래프를 바꿀 수 있어서다 —
  그리는 방법은 플러그인 코드에만 있고, 파일에서 오는 것은 숫자와 #RRGGBB뿐이다.

### 효과 더하기

1. `Core/` 아래에 정의(`VideoEffectDef`)와 그리는 함수를 만든다(`ScanLine.cs`가 본보기).
2. `VideoEffects.All`에 한 줄 더한다.

효과 탭 썸네일, 속성 패널의 매개변수 줄(숫자 슬라이더·색), 저장·검사·복사, 렌더 그래프 자리는 정의에서 저절로 나온다.
묶음(`Group`)은 효과 탭의 묶음 제목과 [묶음] 고르기가 되고(목록에 처음 나오는 차례), 같은 묶음의 효과는 목록에서 붙여 둔다.

그리는 함수의 규칙(`VideoEffects` 설명에도 있음):

- 받는 흐름은 **틀 크기**(`EffectRender.Width`×`Height`)의 gbrap이다. 돌려주는 글을 지금 체인 뒤에 그대로 붙이고, 글이 끝난 곳의 흐름이 효과를 입힌 클립이다(같은 크기, 알파 그대로).
- 라벨은 `EffectRender.Label`로 시작한다. 수식에 `st()`·`ld()`·`random`·`time`을 쓰지 않는다(조각마다 값이 섞이거나 그릴 때마다 달라진다).
- 한 체인에 크기 바꾸기(`scale`)를 둘 잇지 않는다(전환 끝에서 FFmpeg가 멈춘 적이 있다 — [전환 효과](transitions.md)).
- 숫자는 `RenderGraph.N`으로만 쓴다. 길이 값(px 매개변수)은 `EffectRender.PixelScale`을 곱한다.
- 시각은 `t + EffectRender.TimeOffset`(클립 안 시각)으로 쓴다.

## 2. 렌더 그래프에서의 자리

```
원본(-ss·-t·속도·fps) → 틀 맞춤(scale 하나 — 효과가 있으면 바로 gbrap으로) → [맞춤이면 틀 크기로 투명하게 채움]
  → 효과 1 → 효과 2 … → 회전 → 불투명도 → 디졸브 페이드 → 시각 맞춤 → 얹기 / 전환 조각
```

- 효과는 틀 계산(맞춤·채우기·늘이기·흐린 배경, 크기 배율) 뒤, 회전 앞에서 돈다. 그래서 클립과 함께 옮기고 돌고 흐려지고 전환된다(xfade 묶음 안에서도 같다).
- [화면에 맞춤]은 남는 곳이 비어 그림이 틀보다 작다. 효과 앞에서 틀 크기로 투명하게 채운다(`pad … color=black@0`, 그림 자리는 그대로) — 그래서 효과는 늘 틀 크기 그림을 받고, 빈 곳은 계속 투명하다.
- 크기: 효과의 px 값은 프로젝트 픽셀이다. `PixelScale` = 출력 너비 ÷ 프로젝트 너비 × 클립 크기 배율 ÷ 재생 축소(수식 전환 묶음의 재생). 크기 50% 클립은 선도 절반이다.
- 시각: 흐름의 0초는 그리기 시작(`segStart`)이다. 효과 시각 = `t + (segStart − 클립 시작)`초라서, 멈춘 화면(그 프레임부터 그림)·재생(앞에서부터 이어 그림)·내보내기가 같은 프레임을 같게 그린다(시험: 한 장 그리기와 이어 그리기의 픽셀 차 0).
- 효과가 없는 클립의 그래프는 예전과 같다(`format=rgba`).

## 3. 스캔 라인

가는 흰 선(속)을 넓은 색 빛(번짐, 기본 파랑 `#2F7BFF`)이 감싼 띠가 클립 위에서 아래로 훑고 지나간다.

- 선은 **아래로 휜다** — 양끝이 높고 가운데가 처진 얕은 U(휘어짐 0이면 곧은 선).
- 움직임: 주기의 앞 80% 동안 훑고(빨리 들어와 가운데서 머물다 빨리 나감) 나머지 20%는 선이 보이지 않다가 다시 처음부터.
- 어두운 곳을 지날 때는 그 어둠만큼 위아래로 지그재그로 떨린다(일그러짐).
- 스크린으로 섞어 화면을 밝게만 한다. 클립의 알파는 그대로다(투명한 곳은 투명하게).

| 매개변수 | 키 | 범위(기본) | 뜻 |
|---|---|---|---|
| 빛 번짐 | `glow` | 0~150px (40) | 흰 선 둘레 색 빛의 폭. 빛은 이 거리에서 0이 된다 |
| 굵기 | `core` | 1~20px (3) | 가운데 흰 선의 굵기 |
| 휘어짐 | `bend` | 0~100% (35) | 가운데가 처지는 깊이 — 100%면 틀 높이의 20% |
| 일그러짐 | `jitter` | 0~100% (40) | 어두운 곳의 떨림 — 100%면 80px(틀 크기 배율만큼, FFmpeg displace 한도 127px까지) |
| 속도 | `period` | 0.8~6초 (2.4) | 한 번 훑고 다시 시작할 때까지 걸리는 시간(작을수록 빠름) |
| 불투명도 | `opacity` | 0~100% (100) | 선과 빛의 세기 |
| 색 | `color` | #RRGGBB (#2F7BFF) | 빛 번짐의 색(가운데 선은 흰색) |

### 그리기

```
띠 한 장: color(1프레임) → geq(R = 속, G = 번짐) → colorchannelmixer(속 = 흰색, 번짐 = 색, × 불투명도) → tpad(구간 끝까지 그대로)
[일그러짐] 무늬: 두 배 너비 한 줄 geq(꺾은선, 가운데 128) → scale(띠 높이, neighbor) → tpad → crop(1초에 12번 다른 자리)
          어둠: 클립 → crop(띠 자리, 시각 수식) → gray → lut(밝기 140 위 0 ~ 40 아래 다)
          무늬 × 어둠(blend multiply128) = 세로 지도, 가로 지도 = 128 → displace(띠)
검은 틀(color, 틀 크기) + 띠 → overlay(y = 시각 수식) [→ × 인물 마스크(blend multiply)]
→ 클립과 blend: R·G·B는 screen, 알파는 multiply(선 쪽 알파 255 → 클립 알파 그대로)
```

- 띠는 한 번만 그린다(수식 `geq`는 한 장, 나머지는 `tpad`로 같은 그림을 늘인다). 매 장 드는 것은 검은 틀·얹기·섞기와 일그러짐 쪽의 띠 크기 처리뿐이다.
- 휜 선: 띠 안 가로 위치 −1~1에서 선 높이 = 여백 + 처짐 × (1 − x²). 선까지의 거리는 기울기만큼 줄여 굵기가 고르다(`hypot`).
  여백은 번짐 폭 + 떨림 폭 + 1px라 번짐이 띠 가장자리에 닿기 전에 0이 된다(띠 위아래에 딱딱한 줄이 없다).
- 시각 수식(`ScanLine.Progress`와 같은 식): `u = min(1, mod(t + 앞선 초, 주기) / (주기 × 0.8))`, 자리 = `0.25u + 0.75(0.5 + 4(u − 0.5)³)`,
  띠 윗변 = `−띠 높이 + (틀 높이 + 띠 높이) × 자리`. 쉬는 동안은 자리 1(틀 아래로 다 지나감)이다.
- 떨림 무늬는 같은 클립 시각이면 같은 자리를 잘라 쓴다(`floor((t + 앞선 초) × 12)`) — 이어 그려도 한 장 그려도 같다.
- 떨림은 띠 크기에서만 민다. 띠가 틀보다 높아지면(아주 작은 틀) 떨림 폭을 줄이고, 1px 아래면 떨리지 않는다.

### 걸리는 시간 (12스레드 PC, FFmpeg 개발판 N-115012)

| 1080p, 2초(60장) `-f null` | 장당 |
|---|---|
| 효과 없음(320×240 동영상을 채우기로) | 6.2ms |
| 스캔 라인(기본값, 떨림 포함) | 15.0ms (+8.8ms) |
| 스캔 라인(떨림 없이) | 12.2ms (+6.0ms) |

- 목표(장당 +25ms 안팎) 안이다. 시험 `Cost_At1080p_StaysWithinBudget`이 이 셋을 재서 출력한다.
- 띠를 그리는 수식(`geq`)은 그래프마다 한 번이다. 1080p 틀에서 약 0.1~0.2초라, 멈춘 화면을 전체 화질로 그릴 때 그만큼 늦다(1/2 화질이면 약 1/4).

## 4. 사람에게만 (인물 마스크)

- 효과의 [사람에게만]을 켜고 원본의 인물 마스크가 있으면(`RenderOptions.PersonMasks.Find(원본)` — 미리 보기·재생·내보내기는 `RenderEnvironment.PersonMasks`) 사람 자리에만 칠한다.
- 마스크는 원본과 같은 시간축의 흑백 동영상(사진 원본이면 흑백 PNG, 흰색 = 사람)이고 원본보다 작아도 된다.
  - 렌더 그래프는 마스크를 원본과 **똑같이** 읽는다: 같은 `-ss`·`-t`, 같은 속도·`fps`·끝 멈춤, 사진이면 같은 `-loop 1`(`RenderGraph.MediaSource`).
  - 클립과 같은 맞춤으로 틀 크기에 맞춘다 — 크기 바꾸기 한 번(채우기: 키워 가운데 자르기, 늘이기: 틀 크기로, 맞춤·흐린 배경: 줄여 가운데에 두고 남는 곳은 검정).
    마스크는 모델 크기(32의 배수)라 원본과 비율이 조금 달라, 마스크 자신의 비율이 아니라 원본 크기로 FFmpeg의 비율 맞춤과 같은 계산을 해 구한 클립 그림 크기로 늘인다(`RenderGraph.FitSize`) — 가장자리까지 겹친다.
  - 마스크는 원본 화면 시작부터 만든 것이라, 화면이 파일보다 늦게 시작하는 원본은 그만큼(`MediaInfo.VideoStart`) 당겨 읽는다.
  - 효과의 선(검은 틀에 얹은 띠)에 마스크를 곱한 뒤 섞는다(`blend=all_mode=multiply`). 마스크가 검은 곳은 선이 0이라 스크린으로 섞어도 클립 그대로다.
  - 사람에게만 효과가 여럿이면 마스크 흐름을 `split`으로 나눠 쓴다.
- 마스크가 아직 없으면 클립 전체에 칠한다(알파는 그대로). 속성 패널에 "인물 마스크가 없습니다"와 [인물 마스크 만들기]가 보인다
  (`EditorCommands.BuildPersonMask` — 마스크 만들기는 인물 분리 작업). 만든 뒤에는 "인물 마스크 준비됨"(패널을 갱신할 때마다 디스크에서 확인한다).
- 제공자가 없거나 실패하면(예외) 마스크 없이 그린다 — 미리 보기·내보내기가 멈추지 않는다.

## 5. 프로젝트 파일

- `Effects`는 효과가 없으면 쓰지 않는다 — 예전 파일과 형식 번호(2)가 그대로다.
- 너그럽게 읽는다: `Effects`가 목록이 아니면 효과 없음, 형식이 틀린 항목(숫자 자리에 글 등)은 그 항목만 버린다(`LenientListConverter`).
- 열 때 고치기(`VideoEffects.Clean`, 프로젝트 파일은 남이 만든 것일 수 있다):
  - 동영상·사진 클립에만, 8개까지. 빈 항목과 id 형식(영문 소문자로 시작하는 소문자·숫자·`-` 48자)이 아닌 항목은 버린다.
  - 아는 효과: 숫자는 매개변수 범위 안으로(NaN·무한대는 기본값), 모르는 키는 버리고, 색은 대문자 #RRGGBB로(알파는 빼고, 잘못된 색은 기본 색). 빠진 값은 기본값으로 채운다.
  - **모르는 효과는 남겨 두고 그리지 않는다** — 새 판에서 만든 효과가 든 프로젝트를 이 판에서 열어 저장해도 사라지지 않게(전환 효과의 모르는 id와 같은 방식).
    값은 형식이 맞는 키의 유한한 숫자 32개까지, 색은 #RRGGBB이거나 없음. 속성 패널에는 "알 수 없는 효과"와 [빼기]만 보인다.
- 나누기(분할)·복사·붙여넣기는 효과 목록을 깊게 복사한다(`Clip.CloneWithNewId`) — 한쪽 값을 바꿔도 다른 쪽은 그대로.
- 모든 고치기는 실행 취소에 남는다(`EditorCommands.EditClip`). 슬라이더를 끄는 동안은 한 단계로 합치고(매개변수마다 다른 합치기 키), 값을 보이기만 해서는 편집이 생기지 않는다.

## 6. 화면

- 미디어 패널 **[효과]** 탭: 맨 위에 **동영상 효과**, 그 아래 **전환 효과**. 탭 전체가 한 번에 세로로 스크롤된다(안쪽 목록은 스스로 스크롤하지 않고, 목록 위에서 굴린 바퀴도 탭을 스크롤한다).
  - 두 부분 모두 머리글(`▾ 동영상 효과 14`, 아래에 가는 줄)을 누르면 접고 편다(처음에는 펴 둠 — 효과가 많을 때 전환 효과로 바로 가려면 접는다).
  - 동영상 효과는 **묶음마다 제목**(이름 · 개수 ───) 아래에 썸네일 칸을 둔다. 묶음 차례는 목록(`VideoEffects.All`)에 처음 나오는 차례(`VideoEffects.Groups()`).
    [묶음]에서 한 묶음만 고를 수 있다(처음은 "모든 효과" — 전환 효과의 묶음 고르기와 같은 모양).
  - 칸: 폭에 들어가는 만큼 칸 수를 정하고 남는 폭을 칸에 고루 나눈다(`TileGrid` — 칸 폭 104~150px, 좁은 왼쪽 패널에서 두 칸). 모든 칸이 같은 크기이고,
    16:9 썸네일 아래에 이름, 툴팁은 이름 · 묶음과 설명. 전환 효과 칸도 같은 놓기를 쓴다.
  - 썸네일: 합성 그림에 실제로 그린 1.5초 띠 15칸, 마우스를 올리면 움직임(데이터 폴더`\cache\video-effects\<해시>.png`, 그리기는 FFmpeg로 UI 밖에서 3개씩).
  - [고른 클립에 넣기](머리글 줄 오른쪽)·두 번 누르기: 고른 동영상·사진 클립마다 효과를 더한다. 타임라인의 클립으로 끌어 놓아도 된다(동영상·사진 클립 위에서만 놓인다).
    단추는 동영상·사진 클립을 골랐을 때만 켜진다(꺼져 있을 때 툴팁이 까닭을 알림). 두 번 누르기는 그대로 명령을 불러, 글자 클립만 골랐으면 상태 줄에 알린다.
  - 넣으면 그 클립을 고르고 속성 패널 [효과] 탭을 연다. 고른 클립에 이미 든 효과의 칸은 썸네일 둘레와 이름이 강조색이다(자동화 `ItemStatus` "고른 클립에 있음").
  - 자동화 id: `EffectsTabScroll`, `VideoEffectSection`·`TransitionSection`(머리글), `VideoEffectGroup`(묶음), `VideoEffectList`·`VideoEffect_<id>`, `VideoEffectApplyButton`.
- 속성 패널 **[효과]** 탭(동영상·사진 클립만): 효과마다 이름과 그 옆에 작게 묶음(`EffectGroup<n>`), [빼기], 매개변수 줄, [사람에게만]. 사람에게만을 켠 효과가 있으면 인물 마스크 상태와 [인물 마스크 만들기].

### 썸네일 바탕

효과마다 같은 합성 그림(`VideoEffects.PreviewSource`, 128×72)에 그린다. 밋밋한 바탕에서는 글리치·흔들림이 보이지 않아, 무늬와 밝고 어두운 곳을 섞었다:

- 위 72%: 남색에서 분홍으로 가는 하늘(왼쪽일수록 어두움)에 12px 격자, 아래: 8px 흑백 바둑판 바닥, 오른쪽 위: 밝은 해(둘레에 빛), 가운데 왼쪽: 거의 검은 사람 실루엣(머리·목·어깨).
- 격자·바둑판은 흔들림·확대를, 해·실루엣의 또렷한 가장자리는 글리치·색 어긋남을, 어두운 곳은 어둠에 반응하는 효과(스캔 라인의 떨림)를 보여 준다.
- 정지 화면이다(움직임은 효과만). 수식(`geq`)은 한 장만 그리고 `tpad`로 1.5초를 채운다 — 바탕 그리기는 거의 들지 않는다(이 PC에서 FFmpeg 시작 포함 바탕만 0.1초, 스캔 라인 띠 한 장 0.16초).
- 캐시 이름(`PreviewKey`)은 `fx2`와 바탕 글 전체를 넣어 만든다 — 예전 판(밋밋한 바탕)의 썸네일 파일은 다시 쓰지 않고, 바탕을 고치면 저절로 새로 그린다.

## 7. 시험

- `VideoEffectsTests`(Core): 저장·빠짐·너그러운 읽기, 범위·색·모르는 효과 고치기, 동영상·사진에만, 나누기·복사의 깊은 복사,
  그래프 자리(틀 맞춤 뒤·회전 앞, 체인의 scale 하나), 맞춤 채우기, 클립 안 시각(가운데부터 그리기), 인물 마스크 입력(원본과 같은 `-ss`·`-t`·속도, 사진 반복, 찾았을 때만), xfade 조각, 재생 축소·크기 배율, 색 넣기 막기.
- `VideoEffectsRenderTests`(FFmpeg): 띠의 높이가 시각 식과 맞고 뒤 시각에 더 아래·가운데가 처짐·쉬는 동안 없음, 마스크(사진·동영상)의 흰 쪽에만,
  알파(투명한 곳·맞춤의 빈 곳은 아래 트랙 그대로), 어두운 곳의 떨림, 한 장 그리기 = 이어 그리기, 전환·재생(수식 전환 묶음)에서 멈추지 않음, 썸네일 띠, 1080p 걸리는 시간.
- `VideoEffectsTests`(화면): 효과 탭에서 넣기 → 미리 보기가 바뀜, 슬라이더 끄기 = 실행 취소 한 단계, 색, 빼기·되돌리기, 끌어 놓기, 사람에게만·마스크 상태·[인물 마스크 만들기], 글자 클립에는 없음(넣기 단추가 꺼지고 두 번 누르면 알림).
  - 효과 탭 모양: 묶음 제목·[묶음] 고르기(지금 목록으로), 같은 크기 칸·썸네일, 전환 효과가 아래·탭 스크롤·바퀴, 단추는 동영상·사진 클립을 골랐을 때만, 두 번 누르기, "고른 클립에 있음" 강조, 접기,
    속성 패널의 묶음 이름. 캡처 `video-effects-tab`(창)·`video-effects-tab-full`(탭 내용 전체)·`video-effects-tab-group`·`video-effects-applied`·`video-effects-collapsed`.
- 썸네일 바탕(Core·FFmpeg): 인수가 새 바탕을 쓰고 캐시 이름이 예전 판과 다름, 묶음 차례, 바탕이 정지·실루엣이 검고 해가 밝고 바둑판·격자·하늘 밝기 차가 있음.
