# 유튜브에 올리기 (자기 OAuth 클라이언트)

내보낸 동영상이나 이미 있는 동영상 파일을 YouTube Data API v3로 자기 채널에 올린다.
플러그인에는 구글 API 클라이언트 ID·비밀이 들어 있지 않다. 각자 자기 Google Cloud 프로젝트에서 **데스크톱 앱** 유형의 OAuth 클라이언트를 만들어 넣는다.
그래서 할당량과 앱 검증은 그 프로젝트(사용자)의 몫이다.

## 1. 먼저 알아 둘 것

- **검증받지 않은 프로젝트로 올린 동영상은 비공개로 묶인다.**
  - YouTube API 서비스 감사를 받지 않은 API 프로젝트(2020년 7월 28일 뒤에 만든 것)로 올리면, 공개 범위를 "공개"·"일부 공개"로 골라도 비공개로 올라간다.
  - 유튜브 스튜디오에는 "비공개(잠김)"처럼 보이고, 공개로 바꿀 수 없다.
  - 풀려면 그 프로젝트가 YouTube API 서비스 감사(Audit and Quota Extension Form)를 통과해야 한다.
  - 그래서 플러그인은 공개 범위의 기본값을 **비공개**로 둔다. 요청한 공개 범위와 다르게 올라가면 끝난 뒤 알린다.
- **할당량은 그 프로젝트 몫이다.**
  - YouTube Data API v3의 프로젝트 기본 할당량은 하루 10,000 단위다. 동영상 올리기(videos.insert) 한 번은 약 1,600 단위다. 그래서 하루 6번쯤 올릴 수 있다.
  - 할당량은 태평양 시간 자정에 다시 채워진다.
  - 값은 바뀔 수 있으니 [할당량 비용 표](https://developers.google.com/youtube/v3/determine_quota_cost)와 콘솔의 할당량 화면을 확인한다.
  - 다 쓰면 플러그인이 "오늘 쓸 수 있는 … 할당량을 다 썼습니다"라고 알린다. 올리기를 처음부터 다시 하면 할당량을 다시 쓸 수 있다.
- **테스트 모드 앱의 로그인은 7일마다 다시 해야 한다.**
  - 게시 상태가 "테스트"인 외부(External) 앱의 새로 고침 토큰은 7일 뒤 만료된다.
  - 만료되면 플러그인이 [올리기]를 누를 때 브라우저 로그인을 다시 띄운다.

## 2. 설정 순서

콘솔 메뉴 이름은 한국어(영어)로 적는다. 새 콘솔에서는 OAuth 동의 화면 자리가 **Google 인증 플랫폼(Google Auth Platform)** 으로 바뀌었다.
그 아래 브랜딩(Branding)·대상(Audience)·클라이언트(Clients)·데이터 액세스(Data Access)가 있다.

### 1단계. Google Cloud 프로젝트 만들기

1. [Google Cloud 콘솔](https://console.cloud.google.com/)에 올릴 채널의 구글 계정(또는 관리할 계정)으로 로그인한다.
2. 위쪽 프로젝트 고르기 → **새 프로젝트(New project)** → 이름(예: `folderss-upload`) → **만들기**.

### 2단계. YouTube Data API v3 켜기

1. **API 및 서비스(APIs & Services) > 라이브러리(Library)** 에서 "YouTube Data API v3"를 찾는다.
2. **사용(Enable)** 을 누른다.

켜지 않으면 올릴 때 "이 Google Cloud 프로젝트에서 YouTube Data API v3를 켜지 않았습니다"라고 알린다.

### 3단계. OAuth 동의 화면 — 테스트 모드, 자기 계정을 테스트 사용자로

1. **API 및 서비스 > OAuth 동의 화면(OAuth consent screen)** 으로 간다. 새 콘솔이면 **Google 인증 플랫폼 > 시작하기(Get started)** 다.
2. 앱 이름(예: `Folderss 동영상 편집 — 내 채널`), 사용자 지원 이메일, 개발자 연락처 이메일을 넣는다.
3. 대상(사용자 유형)은 **외부(External)** 로 한다.
   - Google Workspace 조직 계정이면 **내부(Internal)** 도 된다. 내부 앱에는 테스트 사용자 목록과 7일 만료가 없다.
   - 내부 앱이어도 1절의 "비공개로 묶임"은 그대로다(유튜브 감사는 따로).
4. 게시 상태는 **테스트(Testing)** 그대로 둔다. **테스트 사용자(Test users) > 사용자 추가(Add users)** 에 올릴 구글 계정(자기 계정)을 넣는다.
   - 테스트 사용자가 아닌 계정으로 로그인하면 구글이 막는다.
   - 그때 플러그인은 "구글 로그인에서 허락하지 않았습니다. 테스트 사용자로 추가하지 않은 계정이면…"이라고 알린다.
5. 범위(데이터 액세스)는 따로 넣지 않아도 된다. 플러그인은 로그인할 때 `https://www.googleapis.com/auth/youtube.upload` 하나만 요청한다.
6. 앱을 **프로덕션으로 게시**하려면 `youtube.upload`가 민감한 범위라 구글 앱 검증이 필요하다. 자기 채널에만 올린다면 테스트로 두면 된다.

### 4단계. 데스크톱 앱 클라이언트 만들기

1. **API 및 서비스 > 사용자 인증 정보(Credentials) > 사용자 인증 정보 만들기(Create credentials) > OAuth 클라이언트 ID(OAuth client ID)** 로 간다.
   새 콘솔이면 **Google 인증 플랫폼 > 클라이언트(Clients) > 클라이언트 만들기(Create client)** 다.
2. 애플리케이션 유형은 **데스크톱 앱(Desktop app)** 이다. 이름은 아무거나 넣는다.
3. 만들면 **클라이언트 ID**(`….apps.googleusercontent.com`)와 **클라이언트 보안 비밀번호(Client secret)** 가 나온다.
   - **JSON 다운로드(Download JSON)** 로 `client_secret_….json`을 받아 두면 편하다.
   - 보안 비밀번호는 만든 직후에만 다시 볼 수 있는 경우가 있으니 바로 받아 둔다.
4. **웹 애플리케이션** 유형은 쓸 수 없다. 플러그인은 127.0.0.1의 빈 포트로 돌아오는 리디렉션을 쓰는데, 이것은 데스크톱 앱 유형만 허락된다.
   JSON 파일이 웹 유형(`"web"`)이면 플러그인이 거절한다.

### 5단계. 플러그인에 넣기

- 방법 1: **Folderss 설정 > 동영상 편집**의 "유튜브에 올리기"에서 넣고 설정 창의 **저장**을 누른다.
  - **JSON 파일에서 불러오기…** 로 4단계의 JSON을 고르거나, ID·보안 비밀번호를 붙여 넣는다.
- 방법 2: 처음 **유튜브에 올리기** 창을 열면 같은 입력 칸이 먼저 뜬다. 넣고 **저장하고 계속**을 누른다.
- 클라이언트 ID는 설정에 그대로 둔다. 보안 비밀번호는 DPAPI(이 Windows 사용자)로 암호화해 설정에 둔다.
- 클라이언트 ID를 바꾸면 그 전 로그인은 쓸 수 없어 지운다.

## 3. 올리기

1. 내보내기가 끝나면 내보내기 창의 **유튜브에 올리기**를 누른다. 이미 있는 파일이면 **파일 > 유튜브에 올리기…** 에서 mp4 등을 고른다.
2. 정보를 넣는다.

   | 칸 | 값 |
   |---|---|
   | 제목 | 기본은 파일 이름. 100자까지, `<` `>`는 안 됨 |
   | 설명 | 5,000바이트까지(한글은 한 글자에 3바이트), `<` `>`는 안 됨 |
   | 공개 범위 | **비공개(기본)** · 일부 공개 · 공개 |
   | 아동용 | 꼭 고른다(유튜브가 채널에 직접 밝히게 하는 값). 고르기 전에는 [올리기]가 꺼져 있다 |
   | 분류 | 고르지 않고 "인물/블로그"(22)로 올린다. 유튜브 스튜디오에서 바꾼다 |

3. 처음이면 **올리기**를 누를 때 시스템 브라우저에 구글 로그인이 뜬다.
   1. 계정을 고른다.
   2. "Google에서 확인하지 않은 앱" 경고가 나오면 **계속**을 누른다(자기 프로젝트의 테스트 앱이라서 나온다).
   3. "YouTube 동영상 관리" 권한을 허락한다. 권한 칸이 있으면 체크한다.
   4. 브라우저에 "로그인했습니다"가 나오면 창으로 돌아온다. 올리기가 바로 시작된다.
   - 5분 안에 마치지 않으면 멈춘다. 브라우저를 열지 못하면 주소를 창에 보여 준다(복사해 브라우저에 붙여 넣는다).
4. 올리는 동안 진행률과 속도를 보이고 **취소**로 멈춘다.
   - 연결이 끊기거나 서버 오류(5xx)면 1·2·4…60초 기다렸다가 서버가 받은 위치를 묻고 그 다음부터 이어 보낸다.
   - 진전 없이 8번 잇달아 실패하면 멈춘다.
   - 1시간 넘게 걸려도 접근 토큰을 새로 받아 이어 간다.
5. 끝나면 동영상 링크(`https://youtu.be/…`)와 **열기**·**복사**를 보인다. 유튜브가 처리를 마치기까지 몇 분 걸릴 수 있다.
   - 같은 파일을 두 번 올려 할당량을 쓰지 않게, 다 올린 뒤에는 [올리기]가 꺼진다.
6. 창을 닫거나 Folderss를 끄면 다음에는 처음부터 다시 올려야 한다(올리기 세션을 저장해 두지 않는다).

## 4. 로그인 정보와 로그아웃

- **로그인 방식**: 설치형 앱 OAuth(RFC 8252).
  - 시스템 브라우저로 연다.
  - 127.0.0.1의 빈 포트로 리디렉션을 받는다(이 PC 밖에서는 닿지 않음).
  - PKCE(S256)를 쓰고, state가 맞는 응답만 받는다.
  - 범위는 `youtube.upload` 하나다.
- **저장**
  - 새로 고침 토큰만 DPAPI(이 Windows 사용자)로 암호화해 `%LOCALAPPDATA%\Folderss\plugin-data\zaruous.folderss-video-editor\youtube\token.dat`에 둔다.
  - 이 PC의 다른 Windows 사용자나 다른 PC에서는 풀리지 않는다. 접근 토큰(1시간)은 메모리에만 둔다.
- **로그아웃**: 설정 탭이나 올리기 창의 **로그아웃**을 누른다.
  - 구글에 토큰 취소(revoke)를 보내고 파일을 지운다.
  - 오프라인 등으로 취소를 보내지 못하면 이 PC의 파일만 지우고 알린다.
    그때는 [Google 계정 > 보안 > 타사 앱 및 서비스와의 연결](https://myaccount.google.com/connections)에서 지운다.
- 토큰·보안 비밀번호·인증 코드는 기록·오류 메시지에 남기지 않는다. 서버가 돌려준 글에 섞여 있어도 지운다.
- **네트워크**: Folderss 본체와 같은 방식이다. Windows 시스템 프록시(자동 구성 스크립트 포함)를 쓰고, 인증 프록시에는 Windows 로그인 자격 증명을 넘긴다.

## 5. 정한 것

1. **자기 클라이언트**
   - 플러그인에 공용 클라이언트를 넣으면 모든 사용자가 한 프로젝트의 하루 할당량(올리기 6번쯤)을 나눠 쓴다.
   - 공개 저장소에 비밀을 둘 수 없고, 감사도 저장소가 받아야 한다.
   - 그래서 각자 자기 프로젝트를 쓰게 했다.
2. **범위는 `youtube.upload` 하나, 재생목록은 넣지 않음**
   - 재생목록에 넣기(playlistItems.insert)는 `youtube` 또는 `youtube.force-ssl` 범위가 있어야 한다.
   - 이 범위는 채널의 동영상·재생목록을 고치고 지울 수 있는 넓은 권한이라, 올리기 하나를 위해 요청하지 않는다.
   - 재생목록·썸네일·자막은 유튜브 스튜디오에서 한다.
3. **Google SDK를 쓰지 않음**
   - 필요한 것은 토큰 엔드포인트 요청 셋(교환·새로 고침·취소)과 재개 가능 업로드(POST + PUT)뿐이라 `HttpClient`로 직접 했다.
   - SDK(구글 .NET 클라이언트 라이브러리)를 쓰면 zip에 의존 DLL이 여럿 늘고, 프록시를 본체와 같게(`HostNetwork`) 맞추는 코드를 따로 짜야 한다.
   - 직접 짜면 가짜 `HttpMessageHandler`로 토큰·조각·이어 보내기를 단위 시험할 수 있다.
4. **DPAPI는 `System.Security.Cryptography.ProtectedData`**
   - 플러그인(net8.0-windows, WPF)은 Windows 데스크톱 공유 프레임워크에 들어 있는 것을 써서 zip이 늘지 않는다.
   - 시험 프로젝트(net8.0)만 같은 이름의 NuGet 패키지(MIT)를 참조한다. Linux CI에서는 가짜 암호화로 시험한다.
5. **리디렉션은 `TcpListener`로 받음**
   - `HttpListener`(http.sys)는 URL 예약·권한 문제가 생길 수 있다.
   - 그래서 127.0.0.1의 포트 0으로 소켓을 열어 빈 포트를 받고, 요청 줄만 읽는다.
   - 연결마다 따로 읽어, 브라우저가 미리 열어 둔 빈 연결이 막지 않게 한다.
6. **조각 8MiB(256KiB의 배수), 요청 하나 10분 한도**
   - 한도를 넘기면 끊긴 것으로 보고 받은 위치를 물어 이어 보낸다.
   - 308 응답은 리디렉션으로 따라가지 않는다(`AllowAutoRedirect = false`).

하지 않은 것(이후 과제): 재생목록, 썸네일, 예약 공개, 태그·분류 고르기, 창을 닫은 뒤 이어 올리기(세션 저장), 여러 계정 전환.
