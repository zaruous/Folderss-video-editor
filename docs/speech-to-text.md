# 음성 인식 자막 (whisper.cpp, 이 PC에서만)

내레이션 영상에 붙일 자막을 편집기 안에서 만든다. 지금까지는 다른 도구로 SRT를 만들어 [자막 가져오기]로 넣어야 했다.
PRD에서 AI 기능은 서버·모델이 필요해 뺐다. 음성 인식만은 서버 없이 로컬 모델로 할 수 있어서 범위에 넣는다.

## 1. 쓰는 법

- [파일 > 음성 인식으로 자막 만들기…]를 누르거나, 타임라인 클립의 오른쪽 메뉴에서 [이 클립 소리로 자막 만들기…]를 고른다.
- 고른 클립 중 소리가 있는 것이 있으면 그 클립만 인식한다. 없으면 타임라인 전체 소리(모든 트랙을 섞은 것)를 인식한다.
  배경 음악이 섞이면 시각이 밀리고 틀린 말이 늘어서, 내레이션 클립을 고르는 것을 권한다.
- 말(한국어·자동·English·日本語·中文)과 모델을 고르고 [자막 만들기]를 누른다. 이름·용어가 자주 나오면 [자주 나오는 낱말]에 쉼표로 적는다(예: 맹자, 반구저기).
- 대본이 있으면 [대본]에 붙여 넣거나 [대본 파일…]로 고른다(.txt·.md, 1MB까지). 글은 대본에서, 시각은 소리에서 가져온다(아래 4절).
- 결과는 맨 위 새 자막 트랙에 큐로 들어간다. 시각은 타임라인 위치(클립이면 클립 시작·속도에 맞춤)이고, 틀린 글은 큐를 골라 속성에서 고친다.

## 2. 정한 것

1. **엔진: whisper.cpp CLI(`whisper-cli.exe`).**
   - 이 PC에서만 돌아서 소리를 인터넷으로 보내지 않는다. 라이선스는 MIT이고 모델 가중치도 MIT다.
   - 처음 한 번 GitHub ggml-org/whisper.cpp 릴리스의 `whisper-bin-x64.zip`(CPU 판, 약 9MB)을 받는다.
     - 릴리스 API의 SHA-256(digest)이 맞을 때만 쓴다.
     - `whisper-cli.exe`와 whisper·ggml DLL만 데이터 폴더`\whisper`에 푼다.
   - whisper.cpp는 버전 태그(v1.x)에는 파일이 없고, 같은 때 만든 빌드 릴리스(bNNNN)에 붙인다.
     그래서 최신 정식 버전과 6시간 안에 만든 빌드를 고르고, 없으면 파일이 있는 가장 새 릴리스를 고른다.
   - 받은 뒤 `--version`을 돌려 본다. Microsoft Visual C++ 재배포 패키지(x64)가 없어 시작하지 못하면(0xC0000135) 설치 주소를 알린다.
2. **모델: Hugging Face ggerganov/whisper.cpp의 양자화 모델 셋.** 크기와 SHA-256은 코드에 고정해 두고, 받은 파일과 맞춰 본다.
   말소리 구간 감지 모델(Silero VAD v6.2.0, ggml-org/whisper-vad, 0.9MB)도 함께 받는다.

   | 이름 | 파일 | 크기 | 2분 30초 내레이션(12코어) |
   |---|---|---|---|
   | 보통(추천, 기본) | ggml-small-q5_1.bin | 190MB | 약 30초. 대체로 맞고 가끔 틀림 |
   | 정확 | ggml-large-v3-turbo-q5_0.bin | 574MB | 약 1분 55초. 단어가 가장 정확 |
   | 빠름 | ggml-base-q5_1.bin | 60MB | 빠르지만 한국어는 자주 틀림 |

3. **인식 순서**
   1. FFmpeg로 16kHz 모노 WAV를 만든다.
      - 클립이면 원본의 클립 구간만 꺼낸다.
      - 타임라인이면 렌더 그래프의 소리를 섞어 쓴다.
   2. `whisper-cli -m 모델 -f wav -l 말 -t 스레드 -ml 1 -sow -osrt -of 이름 -pp --vad -vm VAD모델 [--prompt 낱말]`를 돌린다.
      - 단어(어절)마다 한 큐로 받는다(`-ml 1 -sow`).
        단어 시작 시각은 실제 말 시작(무음 끝)과 중앙값 0.16초, 90%가 0.46초 안에서 맞는다(2분 30초 내레이션, 말 시작 52곳).
      - 말소리 구간 감지(`--vad`)를 켜면 말이 있는 곳만 인식한다.
        배경 음악이 섞인 내레이션에서 첫 큐가 0초로 밀리던 것이 실제 말 시작(2.34초, 내레이션 시작 2초)에 맞는다.
        내레이션만 있을 때는 글이 같고(827자) 첫 큐가 0.32초로 더 정확하다.
      - 진행률은 표준 오류의 `progress = N%`에서 읽는다. 스레드는 코어 하나를 남기고 8개까지 쓴다.
   3. SRT를 읽어 단어를 타임라인 시각으로 옮긴다(클립 시작 + t / 속도). 클립 밖은 자르고 버린다.
   4. 말이 아닌 소리 표시는 뺀다. 괄호 하나로 감싼 `[음악]`·`(박수)`, 그리고 `♪`처럼 음악·잡음에서 모델이 지어내는 것이다.
   5. 단어를 자막 큐로 묶는다(`SpeechText.Group`).
      - 먼저 문장(. ? ! 또는 0.6초 넘는 쉼까지)으로 모은다.
      - 40자(두 줄 남짓)를 넘는 문장은 비슷한 길이로 나눈다. 쉼표 뒤를 먼저, 그다음 이음 어미(-고·-며·-서·-면·-데·-만) 뒤를 고른다.
        그래서 "…싶었습니다."처럼 한 단어만 남는 꼬리가 생기지 않는다.
      - 다음 큐까지 0.5초 안 되게 비면 그 틈까지 늘여 깜빡이지 않게 한다. 단어 시각은 큐에 남긴다(대본 맞춤·단어 강조에 씀).
4. **대본 맞춤**(`SpeechText.AlignScript`) — 대본을 주면 오인식 없이 대본 글 그대로의 자막을 만든다.
   1. 대본을 문장으로 나눈다(`ScriptSentences`).
      - 마크다운 표는 칸마다 먼저 나누고 칸 안의 `<br>`을 줄로 바꾼다.
      - 제목·목록·인용 표시, 강조 기호(`*`), 코드(`` `…` ``), 연출 지시(`*(자막 강조)*`)는 뺀다.
      - 장면 설명·해시태그·설명란처럼 말하지 않는 글은 일부러 고르지 않는다. 소리와 맞는 곳이 없어 저절로 빠진다.
   2. 대본 문장마다 인식한 글(글자·숫자만)에서 가장 비슷한 곳을 찾는다(앞뒤가 공짜인 편집 거리, 35% 이하만).
   3. 대본 순서와 말한 순서가 맞고 서로 겹치지 않는 문장들 가운데, 맞춘 글자가 가장 많은 묶음을 고른다.
      그래서 대본 머리글과 설명란에 같은 인용문이 또 있어도 말한 자리의 것만 쓴다.
   4. 문장 안 단어 시각은 대본 글자를 인식한 글자에 맞춰 정한다. 40자를 넘는 문장은 위와 같은 규칙으로 나눈다.
   5. 대본에 없는 말(애드리브)은 인식한 글 그대로 큐로 남긴다.
   - 2분 30초 내레이션과 그 대본(SCRIPT.md, 장면 설명·설명란 포함 76문장)으로 해 보았다.
     내레이션 문장 29개가 모두 맞고 큐 33개가 전부 대본 글이었다(대본 밖 큐 0개, 17ms).
     "피가 꼽고로" → "피가 거꾸로", "서류처를" → "서류철을", "차짠을" → "찻잔을"처럼 오인식이 사라진다.
5. **임시 파일**: WAV·SRT는 임시 폴더에 무작위 이름으로 쓰고 끝나면 지운다. 클립 Id·파일 이름은 쓰지 않는다.

## 3. 시험

- `SpeechTests`(네트워크·whisper 없이 CI에서 돈다)
  - 릴리스 고르기와 진행률 읽기를 본다.
  - 큐 시각 옮기기, 잡음 표시 빼기, 단어를 큐로 묶기(문장·쉼·길이·쉼표·이음 어미)를 본다.
  - 대본 문장 나누기(표·`<br>`·꾸밈 빼기)와 대본 맞춤(오인식 고침, 애드리브 남김, 같은 인용문이 여러 번 있어도 말한 자리)을 본다.
  - 가짜 응답으로 내려받기·압축 풀기(필요한 파일만, 폴더 탈출 없음)를 보고, SHA-256이 다르면 거부하는지 본다.
- `SpeechIntegrationTests`와 UI 시험의 인식 부분은 `FOLDERSS_VE_WHISPER`를 줄 때만 돈다.
  이 값은 `whisper-cli.exe`와 DLL이 있고 `models\ggml-small-q5_1.bin`이 든 폴더다.

## 4. 범위 밖(다음에)

- GPU 판(CUDA, 270~690MB), 단어 단위 시각(노래방 자막), 화자 나누기.
- 인식한 자막으로 사진 자동 배치(제안 C).
