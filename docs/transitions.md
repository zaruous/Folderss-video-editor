# 전환 효과 — 데이터로 늘리는 구조

클립 사이 전환 효과는 코드가 아니라 데이터(JSON)로 정의한다. 효과를 더하려면 데이터 한 줄을 더하면 된다.

## 1. 어디에 있나

| 곳 | 내용 |
|---|---|
| `src/VideoEditor/Core/transitions.json` | 기본 효과(플러그인 DLL에 포함). 순서가 [전환] 탭에 보이는 순서이고, 첫 효과는 디졸브(`Fade`)여야 한다 |
| 데이터 폴더`\transitions\*.json` | 사용자 효과. [전환] 탭의 [효과 폴더 열기]로 열고, 파일을 넣은 뒤 [다시 읽기] |

## 2. 형식

```json
{
  "transitions": [
    { "id": "WipeLeft", "name": "닦아내기 ←", "group": "닦아내기", "xfade": "wipeleft" },
    { "id": "Heart", "name": "하트", "group": "모양", "expr": "if(lte(...),B,A)" },
    { "id": "CoverLeft", "name": "덮기 ←", "group": "밀어내기", "xfade": "coverleft", "ffmpeg": 7 }
  ]
}
```

| 키 | 뜻 |
|---|---|
| `id` | 프로젝트에 저장되는 이름. 영문으로 시작하는 영문·숫자·`_`·`-` 48자 이내. 기본 효과 id는 바꾸지 않는다(저장된 프로젝트가 그 id로 연다) |
| `name` | [전환] 탭·타임라인에 보일 이름(40자까지) |
| `group` | [전환] 탭의 묶음. 사용자 효과에 없으면 "내 효과" |
| `xfade` | FFmpeg xfade의 내장 효과 이름 |
| `expr` | xfade 수식(`transition=custom`). `xfade`와 `expr` 중 하나만 쓴다 |
| `ffmpeg` | 필요한 FFmpeg 주 버전(선택). xfade 효과가 들어간 버전보다 낮게 적어도 그 버전으로 올린다 |
| `ease` | 수식 효과의 움직임(선택): `linear`(일정 — 없을 때와 같음)·`in`(천천히 시작)·`out`(천천히 끝)·`inout`(둘 다). 내장 `xfade` 효과에는 쓸 수 없다 |

JSON 주석과 끝 쉼표는 받는다. 파일 하나는 1MB, 사용자 효과는 500개까지다.

### 수식(`expr`)

- 값: `X`·`Y` 픽셀 위치, `W`·`H` 화면 크기, `P` 진행(시작 1 → 끝 0), `A` 앞 화면 값, `B` 새 화면 값, `PLANE` 색 평면.
  `a0(x,y)`~`a3(x,y)`·`b0(x,y)`~`b3(x,y)`는 다른 위치의 값(평면 0~3)이다.
- 쓸 수 있는 함수: `if ifnot lt lte gt gte eq between clip not abs min max hypot sin cos tan asin acos atan atan2 sinh cosh tanh sqrt pow exp log floor ceil round trunc mod sgn squish gauss isnan isinf`, 상수 `PI E PHI`.
- 글자는 영문·숫자·공백과 `. , + - * / ^ ( )`만 쓴다. 1500자까지다.
- 수식 효과는 픽셀마다 수식을 풀어서 내장 효과보다 5~10배 느리다(540×960에서 12스레드로도 한 장에 약 84ms).
  - 그래서 미리 보기 **재생** 중에는 수식 전환이 든 묶음을 줄인 캔버스에서 섞고 얹기 전에 늘인다(`RenderOptions.Playback`, `RenderGraph.PlaybackShrink`).
    수식을 푸는 픽셀이 약 14만 개가 되게 줄여, 1/2 화질은 2분의 1, 전체 화질은 4분의 1이고 1/4 화질은 그대로다.
  - 1080×1920 프로젝트의 1/2 화질 재생에서 페이지 넘김 수식 전환이 한 장에 약 136ms(초당 7장)에서 약 30ms로 줄었다.
  - 멈춘 화면 한 장과 내보내기는 원래 크기로 그린다.
  - 줄이기는 틀 계산의 scale에서 바로 한다. 크기 바꾸기(scale)를 두 번 이으면 FFmpeg가 전환 끝에서 멈추는 일이 있었다(10번 중 6번).
- 예: `if(lt(mod(Y,H/8)/(H/8),1-P),B,A)`는 가로 블라인드다.

### 이징(`ease`)

- FFmpeg xfade에는 이징 옵션이 없어(9.0까지), 그릴 때 수식의 낱말 `P`만(`PLANE`·`PI`·`PHI`는 그대로) 이징을 건 식으로 바꿔 넣는다(`Transitions.XfadeOption`).
  진행 u = 1 − P에 in = u², out = 1 − (1 − u)², inout = u²(3 − 2u)(smoothstep)를 건 꼴 — `in`은 `(1-(1-P)*(1-P))`, `out`은 `(P*P)`, `inout`은 `(P*P*(3-2*P))`. 시작(P = 1)과 끝(P = 0)은 그대로다.
- 썸네일 캐시 이름에도 들어간다(이징이 다르면 다른 썸네일). 기본 효과에는 이징을 넣지 않았다(모양 그대로).
- **느려진다**: `P`가 나올 때마다 식이 길어진다. 하트(`P` 8번)에 `inout`을 걸면 540×960에서 같은 그리기가 약 1.6배 걸렸다(4코어 리눅스, FFmpeg 9.0 — 8.0초 → 12.6초).
  무거운 수식에 이징을 걸 때는 미리 보기 재생이 더 끊길 수 있다(재생 축소는 그대로 적용된다).

## 3. 그리기

- 디졸브(`xfade: "fade"`)는 예전처럼 뒤 클립의 알파 페이드로 그린다.
- 나머지는 xfade 묶음으로 그린다. 조각마다 캔버스 크기 투명 바탕에 제자리로 얹고(알파를 곱한 색), 앞 클립과 잇는다.
- 소리(동영상 트랙의 소리 있는 클립)도 효과와 상관없이 겹쳐 바뀐다.
  - 전환이 든 클립의 소리는 전환 동안 sin으로 커진다.
  - 앞 클립의 소리는 원본에서 전환 길이만큼 더 읽어, 클립 끝 뒤로 cos로 줄며 이어진다. 원본이 거기서 끝나면 그만큼 조용하다.
  - 두 곡선을 겹치면 크기감(파워)이 일정하다. 오디오 트랙의 클립은 바꾸지 않는다.
- 쓰는 FFmpeg가 효과에 필요한 버전보다 낮으면 디졸브로 그린다. 그런 효과는 [전환] 탭에도 보이지 않는다.
- 미리 보기 썸네일(`Transitions.PreviewArguments`)은 같은 xfade 옵션으로 128×72 그림 15칸(0.1초 간격)을 그린다.
  - 칸 0~2는 앞 화면, 칸 3~12는 전환, 칸 13~14는 새 화면이다.
  - 그리는 방법이 같으면 같은 캐시를 쓴다(데이터 폴더`\cache\transitions\<해시>.png`).
  - 정지 화면은 칸 8이고, 마우스를 올리면 칸을 차례로 보인다.

## 4. 보안 (효과 파일과 프로젝트 파일은 남이 만든 것일 수 있다)

- 모든 정의는 `Transitions.Check`를 거친다.
  - id·이름 형식을 확인하고, xfade는 아는 이름만, 수식은 위의 글자·이름만 받는다.
  - 그래서 따옴표·`:`·`;`·`[ ]`·`\`로 필터 그래프를 벗어날 수 없다.
- 수식에서 받지 않는 것:
  - 반복(`while`·`root`·`taylor`)과 `random`·`time`·`print`.
  - 상태 변수(`st`·`ld`). xfade가 화면 조각을 여러 스레드로 나눠 풀 때 같은 변수를 함께 써서, 값이 섞인 잡음이 생긴다.
  - 숫자에 붙은 글자(`1e9`, `2k`).
- `squeezev`는 FFmpeg 빌드에 따라 접근 위반으로 죽는다. 그래서 이름으로는 받지 않고, 기본 효과의 "양옆으로 눌러 바뀌기"는 같은 모양을 수식으로 그린다.

## 5. 프로젝트 파일

- 클립의 `Transition`은 효과 id다. 효과 목록이 코드에 있던 때의 이름과 같아서 예전 파일이 그대로 열린다.
- 사용자 효과를 넣은 클립에는 정의(`TransitionDef`)를 함께 저장한다.
  - 그 효과 파일이 없는 PC에서도 같은 효과로 그린다. 기본 효과는 id만 저장한다.
  - 그릴 때는 효과 목록을 먼저 쓴다. 효과 파일의 정의를 고치면 그 고친 것으로 그린다.
- 열 때의 처리:
  - id 형식이 아니거나 형식이 다른 값(숫자 등)이면 디졸브로 바꾼다.
  - 모르는 id는 남기고 디졸브로 그린다.
  - 함께 저장된 정의는 다시 검사한다. 쓸 수 없으면 버리고, 그 값 때문에 프로젝트가 열리지 않는 일은 없다.
